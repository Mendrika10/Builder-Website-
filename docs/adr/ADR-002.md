# ADR-002 — Structure monorepo (apps/web + apps/api)

## Statut

**Accepted** — 17/09/2026 (proposé puis accepté à l'exécution de FOND-001 : le scaffold `apps/web` + `apps/api` existe et tourne)

## Contexte

[ADR-001](ADR-001.md) retient un backend NestJS et un frontend Next.js. Il faut décider comment organiser ces deux applications dans le dépôt.

## Décision proposée

Monorepo simple, géré par npm workspaces (pas d'outil supplémentaire — [règle dépendances](../../AGENTS.md#18-règle-concernant-les-nouvelles-dépendances)) :

```text
/                     # racine : AGENTS.md, docs/, docker-compose.yml
├── apps/
│   ├── web/          # frontend Next.js
│   └── api/          # backend NestJS
├── packages/         # (plus tard) types partagés, contrats API
└── docs/
```

## Alternatives considérées

| Option | Raison du rejet |
|---|---|
| Deux dépôts séparés | Couplage fort des contrats API au démarrage ; PR cross-repo pénibles pour une petite équipe |
| Turborepo / Nx | Outil supplémentaire non justifié tant que le monorepo reste à 2 apps (YAGNI) |

## Conséquences

* Un seul clone, une seule CI pour les deux apps, types partagés possibles via `packages/`.
* La CI devra filtrer les jobs par dossier (ne pas rebuild `apps/web` si seul `apps/api` a changé).
