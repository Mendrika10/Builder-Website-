# ADR-003 — CSS : Tailwind CSS remplace Bootstrap

## Statut

**Accepted** — 17/09/2026

## Contexte

[ADR-001](ADR-001.md) listait Bootstrap dans la stack frontend. Le choix d'UI de référence du produit (qualité de type Wix / Framer / Webflow / Linear / Stripe — voir la règle [UI QUALITY STANDARD](../../AGENTS.md#ui-quality-standard)) exige un contrôle fin de la direction artistique : design tokens, variantes de composants, états d'interaction, responsive précis.

Décision utilisateur (17/09/2026) : adopter **Tailwind CSS** pour le rebuild.

## Décision

* **Tailwind CSS** comme unique framework CSS de `apps/web`.
* Palette, typographie et espacements définis comme **design tokens** dans `tailwind.config.ts` (`extend.colors`, `extend.fontFamily`, `extend.spacing`) — pas de valeurs arbitraires (`bg-[#ff0000]`) répétées dans le code.
* Classes conditionnelles via `clsx`/`cn()`, pas de template strings.
* Composants UI réutilisables dans `components/ui/` — aucune duplication de combinaisons de classes.
* Breakpoints Tailwind par défaut (`sm/md/lg/xl/2xl`) sauf besoin justifié.
* CSS custom uniquement pour ce qui est inexprimable en utilitaires (keyframes complexes).

## Alternatives considérées

| Option | Raison du rejet |
|---|---|
| Conserver Bootstrap | Look « template SaaS » difficile à dépasser ; personnalisation profonde contre-productive ; en conflit avec l'objectif de qualité UI |
| CSS Modules / styled-components | Pas de design tokens intégrés ; risque de dérive entre développeurs/agents |

## Conséquences

* Positives : contrôle total de l'identité visuelle, tokens centralisés (une source de vérité pour tous les agents), écosystème de composants accessible (headless), purge automatique du CSS.
* Négatives / coûts : Bootstrap est retiré de la stack — aucun code Tailwind n'existant encore, la migration est gratuite à ce stade ; les agents doivent utiliser exclusivement les utilitaires (règle intégrée à [AGENTS.md](../../AGENTS.md#stack)).
